MemoFS is a **file-first memory runtime for AI agents**. It bridges the gap between ephemeral agent context windows and persistent codebase evolution by storing decisions, architectural constraints, project conventions, and search indexes directly as **Markdown and JSONL files in your repository**.

<Callout type="info" title="Designed for Two Primary Paths">
Whether you are a developer **using AI coding agents day-to-day** (Claude Code, Cursor, Codex, Copilot, Cline) or an engineer **building custom AI agents and agentic systems**, MemoFS provides the standard runtime for structured, persistent agent memory.
</Callout>

## The 4-Stage Agent Memory Loop

Every effective AI agent follows the four-phase MemoFS memory cycle:

      At the start of every session or task, the agent calls <code>memofs.context</code> to load core rules, architecture constraints, and recent briefing fragments.

  <div className="rounded border border-dashed bg-fd-card p-5 border-l-4 border-l-purple-500">

## The Mental Model in 3 Core Tenets

<Accordions>
  <Accordion title="1. Memory is files, not an external database">
    Core facts, notes, conversation history, recall indexes, and knowledge graph relations all live under `.memofs/` in your repository as Markdown and JSONL. They can be inspected in any editor, version-controlled with Git, and reviewed in Pull Requests just like code.
  </Accordion>
  <Accordion title="2. Every capability has a deterministic fallback">
    Retrieval, graph extraction, and search all work with zero API keys out of the box using local BM25 ranking and regex rule-based parsers. Adding an LLM or embedding adapter (OpenAI, Voyage, Transformers, Cloudflare Workers AI) seamlessly upgrades them to hybrid search without changing your codebase.
  </Accordion>
  <Accordion title="3. Universal protocol distribution">
    Whether an agent supports native lifecycle hooks (Claude Code, Codex, opencode) or standard Model Context Protocol (MCP) tool calling (Cursor, Copilot, Cline, Aider), MemoFS adapts seamlessly across environments.
  </Accordion>
</Accordions>

## Architectural Comparison

<Tabs items={["MemoFS", "Flat AGENTS.md / CursorRules", "External Vector DB"]}>
  <Tab value="MemoFS">
    - **Storage**: Plain Markdown & JSONL in `.memofs/`
    - **Offline Execution**: 100% local, 0 external API keys required
    - **Search**: BM25 keyword + optional vector hybrid search + knowledge graph
    - **Collaboration**: Git-versioned with optional cloud edge replication
    - **Transparency**: Fully human-auditable and editable in any IDE
  </Tab>
  <Tab value="Flat AGENTS.md / CursorRules">
    - **Storage**: Single monolithic static markdown file
    - **Context Window**: Consumes large token volume unconditionally on every prompt
    - **Search**: None (agent must read entire file into context)
    - **Persistence**: Agent cannot reliably self-update without overwriting prompt files
    - **Scalability**: Degrades rapidly as project context grows beyond a few pages
  </Tab>
  <Tab value="External Vector DB">
    - **Storage**: Opaque vector embeddings in proprietary cloud database
    - **Offline Execution**: Fails without internet or external API keys
    - **Search**: Semantic vector similarity only (poor for exact symbol/error matching)
    - **Collaboration**: Disconnected from Git history and PR review flows
    - **Transparency**: Impossible to inspect or edit memory in standard text editors
  </Tab>
</Tabs>
